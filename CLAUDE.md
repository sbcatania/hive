# Claude Code Instructions — Hive

## Layout
- **engine/** — Rust crate: rules, notation (UHP), alpha-beta AI, neural net + MCTS, WASM bindings (`src/wasm.rs`, feature `wasm`), native self-play/arena binaries (feature `native`).
- **web/** — Next.js 15 app (React 19, Tailwind 4). Game logic runs client-side in WebAssembly; the AI runs in a Web Worker (`src/workers/ai.worker.ts`).
- **web/src/wasm/** and **web/public/wasm/** — generated by `scripts/build-wasm.sh` and committed, so Vercel needs no Rust toolchain.
- **training/** — local-only PyTorch training pipeline for the Expert network (not deployed).
- **supabase/migrations/** — schema + RPCs for online games (project `hive`, ref `fqwqbussblwulpehjpjv`).

## Commands
- `cargo test -p hive-engine` — rules tests (perft + move sets from Mzinga, random-game invariants)
- `./scripts/build-wasm.sh` — rebuild WASM after any engine change, then commit the outputs
- `cd web && npm run dev` / `npx next build` — run / build the site
- `cargo run --release --features native --bin arena -- hard medium 16 300` — CPU strength check
- Rust may not be on PATH: `export PATH="$HOME/.cargo/bin:$PATH"`

## Conventions
- Types crossing the WASM boundary are mirrored in `web/src/lib/engine-types.ts` — keep in sync with `engine/src/wasm.rs`.
- NN input encoding lives only in `engine/src/features.rs`; Python reads encoded data, never encodes. Changing features requires retraining.
- Commit and push to main after each logical unit of work; concise messages focused on why.
