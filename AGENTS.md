# Agent Instructions — Hive

## Layout
- **engine/** — Rust crate: rules, notation (UHP), alpha-beta AI, neural net + MCTS, WASM bindings (`src/wasm.rs`, feature `wasm`), native self-play/arena binaries (feature `native`).
- **web/** — Next.js 15 app (React 19, Tailwind 4). Game logic runs client-side in WebAssembly; the AI runs in a Web Worker (`src/workers/ai.worker.ts`).
- **web/src/wasm/** and **web/public/wasm/** — generated by `scripts/build-wasm.sh` and committed, so Vercel needs no Rust toolchain.
- **training/** — local-only PyTorch training pipeline for the Expert network (not deployed).
- **supabase/migrations/** — schema + RPCs for online games (project `hive`, ref `fqwqbussblwulpehjpjv`).
- **gameboy/** — separate Game Boy Color / ModRetro Chromatic port in C (GBDK-2020). It shares no code with the web version: base game only, its own AI, a 32 KiB ROM. See `gameboy/README.md`.

## Commands
- `cargo test -p hive-engine` — rules tests (perft + move sets from Mzinga, random-game invariants)
- `./scripts/build-wasm.sh` — rebuild WASM after any engine change, then commit the outputs
- `cd web && npm run dev` / `npx next build` — run / build the site
- `cargo run --release --features native --bin arena -- hard medium 16 300` — CPU strength check
- `cd gameboy && ./scripts/build.sh && make test` — build the Game Boy ROM (GBDK in `~/gbdk` or `$GBDK`); check its C rules against the Rust engine
- Rust may not be on PATH: `export PATH="$HOME/.cargo/bin:$PATH"`

## Web app map
- `src/app`: `/` start screen, `/play?id=` CPU & pass-and-play (games live in the journal, `src/lib/journal.ts`), `/online?g=`, `/replay`, `/journal`, `/learn` (field guide), `/puzzles` (`src/lib/puzzles.json`, made by `cargo run --release --example find_puzzles`), `/account`, `/player?u=`, `/leaderboard`.
- Design tokens are CSS variables in `src/app/globals.css` (day + `[data-theme=dark]` night); use the Tailwind token classes (`bg-card`, `text-ink`, `border-line`...) rather than raw colours so both themes stay readable. Design rationale: `docs/DESIGN.md`.

## Design system (Sam's, applies to all UI work)
Sam keeps a cross-project design system in Notion: https://app.notion.com/p/40cb6198cc3a8141b858c81acf886610. Read it before building or changing UI and run its checklist before calling UI work done. Hive's own rules in `docs/DESIGN.md` win where they differ; how each rule maps onto Hive is in the "Sam's design system" section there. In short:
- Headings `text-wrap: balance`, paragraphs `pretty` (set globally in `globals.css` base layer); `antialiased` is on `body`.
- `tabular-nums` on anything that counts or ticks (clocks, ratings, move numbers, scores).
- Nested rounded corners: outer radius = inner radius + padding.
- No box-shadows or borders on Hive's chrome: edges are the hand-drawn `.pencil` outlines (Hive rule, overrides the Notion "shadows instead of borders" rule).
- Icon swaps use `<SwapIcon>` (`components/Icon.tsx`), never a hard cut.
- Interruptible interactions (hover, toggles, sheets) use transitions; keyframes only for one-shot sequences. Enters are staggered, exits shorter and quieter. Respect `prefers-reduced-motion`.
- Optically centre icon buttons and icon+text buttons by eye.

## Conventions
- Types crossing the WASM boundary are mirrored in `web/src/lib/engine-types.ts` — keep in sync with `engine/src/wasm.rs`.
- NN input encoding lives only in `engine/src/features.rs`; Python reads encoded data, never encodes. Changing features requires retraining.
- The Game Boy rules (`gameboy/src/rules.c`) are a C mirror of the base-game rules in `engine/src/game.rs`. After changing base-game rules in the engine, run `make test` in `gameboy/` and port the change if it fails.
- Never commit cartridge dumps (`gameboy/cartridge-backup/*.gbc`, `*.sav`); they're git-ignored.
- Commit and push to main after each logical unit of work; concise messages focused on why.

## Ask before anything destructive
SQL and Supabase tools run without a permission prompt in this repo, so this check is on you. Before doing anything that deletes or overwrites data or is hard to undo, say exactly what you'll run and what it affects, then wait for a clear yes in chat. That includes:
- SQL that removes or rewrites existing data or schema: `DELETE`, `UPDATE`, `DROP`, `TRUNCATE`, `ALTER ... DROP`/`RENAME`, revoking grants or RLS policies
- Supabase: applying migrations to the remote project, `supabase db reset`/`db push`, deleting or resetting branches, pausing or restoring the project, changing secrets
- Git: force pushes, `reset --hard`, deleting branches, rewriting pushed history
- Deleting files you didn't create in this task

Read-only work (`SELECT`, listing tables, logs, advisors) and purely additive changes in local files don't need asking.
